# Ранжирование исполнителей

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m unittest -v
```

Первый запуск скачивает модель из Hugging Face. Загрузка модели и построение
эмбеддингов выполняются до приёма запросов, отдельно в каждом процессе сервера.

```python
from ranking import FindRequest, initialize_ranking, rank_and_explain

# Один раз в startup/lifespan сервера, весь исходный датасет:
initialize_ranking(contractors)

# В обработчике — результат filters.py, в исходном формате словарей:
req = FindRequest(event_format="Корпоратив с живой музыкой",
                  budget_kzt=200000, language="RU", duration_hours=4)
result = rank_and_explain(filtered_candidates, req)
```

Обязательные поля: уникальный `id` и непустой `description`. Для объяснений:
`price_from_kzt` (число), `languages` (список строк), `max_hours` (число или null).
ID приводится к строке для сравнения, поэтому `1` и `"1"` считаются одним ID.
Язык сопоставляется точно; фильтр и запрос должны использовать единые обозначения.
Можно заменить локальный FindRequest импортом вашей схемы с теми же полями.

Ответ — исходные поля плюс `score` (cosine similarity от −1 до 1) и
`explanation`. Порядок: score по убыванию, строковый id по возрастанию.
Цена, язык и длительность — критерии объяснения; жёсткую фильтрацию выполняет
filters.py. Веса и top-k не вводятся без требований продукта.

Описания кодируются пакетно при инициализации. Эмбеддинги запросов кэшируются
в памяти (256 форматов); изменение датасета требует повторной инициализации.
Нулевые векторы дают score=0. Неизвестный ID или изменённое описание вызывают
явную ошибку, а не скрытый пересчёт в обработчике.

Объяснения используют шаблоны и цитату из description. Совпадающие исходные
данные могут дать одинаковые объяснения: гарантировать различие фактов без
различий в датасете невозможно. Семантический score не выдаётся за подтверждение
доступности или опыта работы в определённом формате. Description — текстовые
данные, в интерфейсе его нужно выводить с обычным HTML-экранированием.

Опциональный LLM-слой не включён: основной путь не зависит от внешнего API.
Тесты используют подставной encoder и проверяют логику, а не качество модели.
Лимит 10 секунд требует замера на целевом оборудовании после прогрева модели;
один temperature=0 сам по себе не гарантирует воспроизводимость внешнего LLM.

Проверено локально: 5 unit-тестов прошли. Реальная модель для запроса «Живая
музыка на корпоратив» поставила музыканта (0.8006) выше фотографа (0.1861).
Первый запрос после инициализации и повторный запрос вместе заняли 0.016 с
на двух демонстрационных записях; это не нагрузочный тест полного датасета.
Проверенное окружение: Python 3.9, sentence-transformers 5.1.2, numpy 2.0.2.
Точные версии зависимостей сохранены в requirements.lock.txt.
